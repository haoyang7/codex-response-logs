# Codex Response Logs

本地、只读的 Codex 响应日志查看器。将 SSE / WebSocket 日志与本地会话关联，在浏览器中查看请求参数、首次与最终响应档位、时间、Token 用量和错误。

使用 Python 标准库和原生 HTML / CSS / JavaScript，无需安装 pip 或 npm 依赖，也无需 API key。项目采用 MIT License，是独立社区工具。

## 功能

- **请求与响应对照**：分别展示「请求 → 首次 → 最终」推理档位，以及请求和返回的模型。
- **实时记录**：查看完成、失败、限流、未完成及响应中状态，按对话、模型或 ID 搜索，筛选不一致、失败和待关联记录。
- **完整详情**：展开查看时间来源、Token 明细、错误、会话与轮次，并复制响应 ID 或全部 34 个解析字段的 JSON。
- **方便阅读**：支持暂停更新、保留滚动位置、回到最新、键盘操作和窄屏布局。
- **主题切换**：浅色、深色、跟随系统，默认跟随系统并记住选择。

## 快速开始

需要 Python **3.11+**（包含标准库 `sqlite3`）和现代浏览器。默认桌面日志路径与双击脚本面向 macOS；其他环境可以指定已有日志，桌面应用集成需按实际环境验证。

### 1. 让 Codex 写出响应日志（macOS）

首次使用时，先启用响应事件日志。**只启动查看器不会自动开启 Codex 日志，也无法补采历史上未记录的字段。** 已有完整响应日志时可直接跳到第 2 步。

先结束进行中的任务并**完全退出桌面应用**（可能显示为 Codex 或 ChatGPT），再通过应用标识启动：

```sh
open -b com.openai.codex \
  --env 'RUST_LOG=warn,codex_api=trace,tungstenite::protocol=trace,tungstenite::protocol::frame=off' \
  --env 'CODEX_MAX_LOG_LEVEL=debug'
```

macOS 会按系统注册的应用位置启动，兼容不同的应用文件名和安装目录。若提示找不到应用，见 [启动与停止问题](docs/logging.md#启动与停止问题)。

这些环境变量作用于新启动的 Codex 进程；刷新查看器页面不会应用它们。不同桌面版本可能改变日志格式或级别传递方式，以实际写出的事件为准。调试日志可能包含请求与对话内容，并增加磁盘占用。

### 2. 启动查看器

克隆仓库并启动（也可以下载源码后进入项目目录）：

```sh
git clone https://github.com/haoyang7/codex-response-logs.git
cd codex-response-logs
python3 --version
python3 codex_sse_watch.py --web -n 200
```

浏览器会打开 <http://127.0.0.1:8765/>。请保留终端运行；关闭网页不会停止采集，终端中按 Ctrl+C 退出。Python 脚本和 HTML 文件需要放在同一目录，通过本机服务访问页面。

macOS 也可以双击 `scripts/start.command` 启动，双击 `scripts/status.command` 查看状态，或双击 `scripts/stop.command` 停止本目录实例。脚本使用 PATH 中的 `python3`。

### 3. 确认采集

首次启动会先读取已有日志，再关联本地会话。页面显示当前阶段及读取进度；历史日志越多，首次加载越久。`-n 200` 限制展示条数，不限制扫描范围，以保留早期首档和请求参数。

在 Codex 中发起一个新请求，查看表格是否出现记录。页面没有记录时，展开底部「字段说明与采集状态」，按 [日志配置与排查](docs/logging.md) 检查应用是否完全重启、日志路径与实际写入情况。

使用自定义 Codex 目录、单独的日志文件或其他系统时，见 [数据来源与路径配置](docs/logging.md#数据来源)。

## 常用命令

```sh
# 保持终端运行，不自动打开浏览器
python3 codex_sse_watch.py --web --no-open -n 200

# 自动选择空闲端口，访问终端打印的地址
python3 codex_sse_watch.py --web --port 0 -n 200

# 查看状态或停止指定端口的本目录实例
python3 codex_sse_watch.py --status --port 8765
python3 codex_sse_watch.py --stop --port 8765

# 一次性输出最近 20 条记录，包含失败和待关联响应
python3 codex_sse_watch.py --once --json -n 20

# 只解析指定日志文件；替换为自己的实际路径
python3 codex_sse_watch.py --web --log /path/to/response.log -n 200
```

| 参数 | 用途 |
| --- | --- |
| `--web` | 启动本机网页；默认端口为 `8765` |
| `-n N` / `--lines N` | 最近记录数量，默认 `20`；快速开始和双击脚本使用 `200`，网页最多展示 `5000` 条 |
| `--port N` | 指定端口；启动时 `0` 表示自动分配，状态与停止命令须使用实际端口 |
| `--thread ID` | 只显示指定会话 |
| `--once --json` | 输出一次完整解析元数据后退出 |
| `--home PATH` | 指定 Codex 配置目录；默认取 `CODEX_HOME` 或 `~/.codex` |
| `--log FILE` | 只读取一个日志文件 |
| `--log-dir DIR` | 覆盖常规日志目录 |
| `--desktop-log-dir DIR` / `--no-desktop` | 指定桌面日志目录，或禁用桌面日志读取 |

全部参数见 `python3 codex_sse_watch.py --help`。默认命令行简表仅输出完成且已关联会话的响应；查看失败或待关联记录请使用网页或 `--once --json`。命令行持续监控可用 `-n 0` 跳过已有记录，网页模式要求 `-n` 大于 `0`。

同一目录、同一端口重复启动会复用已认证的实例，沿用原实例配置。更改数据源或展示数量时，先停止实例再重新启动。

## 如何阅读记录

表格保留时间、状态、传输方式、对话、请求与返回模型、推理档位和推理 Token。「传输」列显示 `SSE` 或 `WS`（WebSocket），未知显示 `—`，悬停可查看完整名称。「模型」列分行标注请求与返回，长名称可查看完整提示；其他信息放在行末展开的详情里。

| 显示 | 含义 |
| --- | --- |
| `请求 → 首次 → 最终` | 本地请求参数、`response.created` 返回值、第一条终态事件返回值，分别取证 |
| `—` / JSON 中的 `null` | 没有可靠记录，或会话关联尚未到达；不会补成默认档位 |
| `…` | 响应仍在进行，等待终态 |
| `0` | 日志明确记录的零值 |
| 待关联 | 响应已到达，等待会话记录提供精确关联 |
| 不一致 | 已知且可比较的请求与返回字段存在差异 |

首档与最终档相同表示两个阶段记录的值相同，不是界面回填。失败响应也可能返回 `max` 等档位，这只能说明服务端声明的字段，不能证明请求成功或实际执行的推理强度。

界面时间使用北京时间（`Asia/Shanghai`），并标明请求开始、响应创建或日志记录等来源。服务端响应历时不等于客户端完整请求耗时；没有可靠来源的耗时和 HTTP 状态保持未知。

按 `/` 搜索，按 Esc 清除搜索或收起详情。暂停更新用于固定当前阅读内容，后端仍继续采集。字段的精确定义见 [字段说明](docs/fields.md)。

## 性能与数据保留

后端每秒检查增量，复用未改变的行和会话元数据；页面通过 ETag 长轮询接收变化，空闲等待最长 25 秒。前端复用行节点，关闭详情后释放相应引用。

后端最多保留 **5000 条响应**，默认启动示例展示最近 **200 条**。响应和常用关联缓存在内存；被淘汰的关联及请求参数存入系统临时目录中的私有 SQLite 索引，供迟到响应准确恢复，正常退出时删除。临时索引的磁盘占用随被淘汰的关联数量增长，重启后仍从原始日志恢复。5000 条上限不等于总内存上限：文件数、会话数、单条内容和并发连接也会影响占用。

原始日志由 Codex 写入，表格条数限制不会限制磁盘日志增长。读取支持追加、常见轮转和截断重写；有限采样不能保证识别采样位置均未变化的任意原地改写。未落盘、被删除或损坏且无法确认边界的记录可能无法恢复。

## 隐私与适用范围

查看器只读 Codex 的原始日志与会话数据库，自行管理上述临时关联索引，不直接调用 OpenAI API。HTTP 仅监听 `127.0.0.1`；页面与数据接口校验 Host / Origin，状态和停止接口还需要本实例的临时令牌。

只读接口信任本机进程，不隔离同一机器上的其他账户。请在可信本机环境使用，避免通过代理公开到网络。`.runtime/` 保存临时控制凭据，已加入 `.gitignore`。

调试日志可能包含请求和对话正文。公开提交或反馈问题前，应使用合成或充分脱敏的样本；不要上传真实日志、会话、数据库、个人配置、控制凭据或真实会话截图。

Codex 数据库名称、表结构与日志包装属于内部实现，应用升级后可能需要适配。配置和常见问题见 [日志配置与排查](docs/logging.md)。
